# Модель данных и JSON композиции

Контракты SVG-записей, JSON-композиции и файлового каталога. Сопутствующий документ: [architecture.md](architecture.md). Рабочее хранение — файлы на диске; формат композиции — schemaVersion 1.

## Типы персистентных данных

```ts
interface SvgRecord {
  id: string;
  name: string;
  svgContent: string;
  createdAt: string; // ISO 8601 UTC
}

interface ComponentInstance {
  id: string;
  componentId: string; // происхождение; не внешний ключ
  svgContent: string;  // полный автономный SVG, включая зависимости
  x: number;
  y: number;
  scaleX: number;
  scaleY: number;
  rotation: number; // градусы
  zIndex: number;
}

interface CompositionProject {
  schemaVersion: 1;
  id: string;
  name: string;
  width: number;
  height: number;
  instances: ComponentInstance[];
}

interface StoredComposition extends CompositionProject {
  updatedAt: string; // ISO 8601 UTC
}
```

Служебное поле `nameKey` добавляется к каждой записи только в IndexedDB: trim + Unicode NFC + нижний регистр. Оно не входит в JSON-контракт проекта. ID — строка UUID для новых пользовательских записей; стартовые образцы имеют стабильные строковые ID. Имена заканчиваются на `.svg` или `.json`; пользователь может вводить базовое имя или имя с одним соответствующим расширением. Расширение не удваивается.

## Файловое хранилище

Рабочая папка — `project-files/`, либо явно заданный `PEEPS_DATA_DIR`. В `sources/` и `components/` хранятся исходный и автономный SVG-текст, в `compositions/` — JSON StoredComposition. Файл `library.json` содержит:

```ts
interface FileEntry {
  id: string;
  name: string;
  path: string;       // sources|components|compositions/<UUID>.svg|json
  createdAt?: string; // SVG
  updatedAt?: string; // JSON
}
interface FileCatalog {
  version: 1;
  migrations: string[]; // SHA-256 ранее перенесённых наборов IndexedDB
  sources: FileEntry[];
  components: FileEntry[];
  compositions: FileEntry[];
}
```

Каталог связывает пользовательское имя с безопасным UUID-путём. Текст SVG читается из соответствующего .svg, проект — из .json. При изменении композиции пишется новый файл и атомарно заменяется каталог; старый файл остаётся. Удаление исключает запись из каталога, физические версии сохраняются. Переименовывать файлы вручную или удалять старые версии без проверки ссылок каталога не следует. Для переноса достаточно скопировать всю папку при остановленном сервере.

Уникальность имени проверяется по nameKey под файловой блокировкой. При сохранении композиции expectedRevision сравнивается с updatedAt текущей записи до переключения каталога. Контроль ревизии, проверка имени и смена каталога выполняются в одной критической секции, общей для процессов dev/preview, использующих эту папку. Неуспешная запись каталога оставляет доступной прежнюю версию.

Формат каталога и schemaVersion проекта независимы. Переход не добавляет UI-поля в JSON и не меняет значения трансформаций. При переносе прежних данных SVG остаётся исходной строкой, конфликтующие записи сохраняются отдельными копиями; прежняя база не удаляется. Отпечаток предотвращает повторный перенос того же набора и восстановление удалённой после переноса записи.

## IndexedDB-адаптер для переноса и тестирования

Схема прежней базы: `peeps-svg-constructor`, версия 1, ровно три таблицы. Рабочий редактор больше не использует её для новых записей; она читается при переносе. Изолированный режим test-browser сохраняет этот адаптер для прежних тестов.

| Таблица | Данные | Индексы Dexie |
| --- | --- | --- |
| sources | SvgRecord + nameKey | `id, &nameKey, createdAt` |
| components | SvgRecord + nameKey | `id, &nameKey, createdAt` |
| compositions | StoredComposition + nameKey | `id, &nameKey, updatedAt` |

`id` — первичный ключ. `&nameKey` — уникальный индекс внутри таблицы, защита от гонок между вкладками. Одинаковые имена в разных библиотеках допустимы. Конфликт новой записи не означает разрешения перезаписать существующую. Перезапись композиции выполняется по тому же ID с обновлением updatedAt.

Запись исходника хранит исходный прочитанный SVG-текст, а не URL файла или миниатюру. Компонент хранит автономный SVG. Локальные object/data URL создаются только для отображения и не попадают в базу. Сетевой запрос не выполняется внутри IndexedDB-транзакции.

## JSON-пример

```json
{
  "schemaVersion": 1,
  "id": "composition-example",
  "name": "Моя сцена.json",
  "width": 1200,
  "height": 800,
  "instances": [
    {
      "id": "instance-example",
      "componentId": "component-example",
      "svgContent": "<svg xmlns=\"http://www.w3.org/2000/svg\" viewBox=\"0 0 20 20\"><circle cx=\"10\" cy=\"10\" r=\"8\"/></svg>",
      "x": 160,
      "y": 150,
      "scaleX": 1,
      "scaleY": 1,
      "rotation": 0,
      "zIndex": 0
    }
  ]
}
```

Это иллюстрация формата, не генерация графики для пользовательской библиотеки. Импорт и скачивание JSON через интерфейс не предусмотрены; JSON — формат проекта на диске.

## Инварианты

1. Формат холста — 1200 × 800. Координаты и трансформации конечные; масштабы положительные. Временные пустые сцены допустимы только в редакторе; сохранённая композиция содержит хотя бы один экземпляр.
2. ID экземпляров уникальны внутри композиции. zIndex задаёт порядок от заднего к переднему; при сохранении нормализуется к 0…N−1. Массив записывается в том же порядке.
3. svgContent экземпляра копируется при добавлении из компонента; изменение или удаление библиотечного компонента не меняет снимок.
4. Удаление исходника не удаляет компоненты. Удаление компонента не меняет открытые/сохранённые композиции. Удаление композиции не меняет источники или компоненты. Каскадных удалений нет.
5. componentId — метаданные происхождения, его отсутствие в библиотеке допустимо. Для отображения сцены запрос компонента не нужен.
6. createdAt/updatedAt — метаданные хранения. Диалог, выделение, режим, раскрытые папки, baseline и zoom отсутствуют в персистентном JSON.
7. Неуспех транзакции не снимает dirty и не завершает переход. Нельзя показывать «сохранено» до успешного ответа файлового API.
8. После перезагрузки восстанавливаются сохранённые библиотеки, а не несохранённый черновик. Очистка данных сайта не удаляет файловую библиотеку. Перенос/резервирование выполняются копированием project-files целиком; автоматической синхронизации между компьютерами нет.

## Проверки модели

Реальные браузерные проверки IndexedDB-адаптера включают: добавление/повторное открытие базы, Unicode/case-конфликты имён и конкурентные записи, удаление, сохранность SVG экземпляра после удаления компонента, отказ некорректным композициям. Файловые проверки охватывают перезапуск сервиса, конкурентные записи, отказ записи каталога и повторный перенос. Сквозные проверки дополнительно открывают библиотеку в новом браузерном контексте и проверяют сохранность SVG-снимков.

## Координаты и трансформации

Номинальные размеры w/h берутся из viewBox компонента, либо числовых width/height. Для старых SVG без размеров принят fallback 250 × 450. Ширина экземпляра равна w × scaleX, высота — h × scaleY. x/y — верхний левый угол этой рамки до поворота. Центр cx = x + w × scaleX / 2, cy = y + h × scaleY / 2. Rotation задаётся в градусах вокруг центра и может выходить за 360 после нескольких оборотов.

Эквивалентный SVG-transform: `translate(cx cy) rotate(rotation) scale(scaleX scaleY) translate(-w/2 -h/2)` для локального viewport компонента. Ненулевое начало собственного viewBox обрабатывает само SVG-изображение. Параметры сохраняются полными JS-числами; форматирование поля до трёх знаков не переписывает состояние без изменения ввода. Коэффициент 0,6 и процент просмотра относятся только к экрану.

Масштабы остаются положительными: при пересечении противоположного края размер ограничен 0,01 единицы, отражение не выполняется. Порядок массива и zIndex сохраняют наложение; другие экземпляры и библиотечные компоненты независимы. Рамка определяется естественными размерами SVG и масштабами экземпляра.

До изменения состояния, открытия и сохранения проверяются также вычисленные ширина, высота и центр. Модули x/y и размеры ограничены 1 000 000, модуль угла — 1 000 000 000°, положительный масштаб — 1 000 000 000. Проверяется конечность произведений и обратных масштабов. Невалидная прежняя запись не открывается, но не удаляется из базы. Эти проверки не округляют допустимые значения и не меняют схему JSON.

Рабочий baseline является массивом снимков значимых полей экземпляров, а не JSON-строкой. Строки SVG сохраняются по ссылке; URL превью и диагностическая совместимость отсутствуют в снимке. Сравнение учитывает порядок массива и точные значения, поэтому полная отмена изменения возвращает состояние «сохранено». Baseline по-прежнему не записывается в проект.

## Сохранение и экспорт

При открытии композиции рабочее представление получает `revision` из `updatedAt` записи. Ревизия передаётся отдельно от CompositionProject как ожидаемая версия при перезаписи; UI-поле не сериализуется в проект. Файловый сервис под блокировкой читает текущую запись каталога, сравнивает версию, пишет новый JSON и переключает каталог. В прежнем IndexedDB-адаптере использовалась read/write-транзакция. Новый updatedAt строго больше предыдущего даже при нескольких сохранениях за миллисекунду. Новая запись требует отсутствия ID, перезапись — совпадения ожидаемой версии и существующей записи. Конфликт/удаление оставляет черновик; сохранение копии создаёт новый ID и имя. Схема IndexedDB не меняется.

SVG-экспорт использует текущий массив экземпляров в порядке слоёв, не библиотечные оригиналы. Корень имеет width=1200, height=800, viewBox=0 0 1200 800. Каждый экземпляр — группа с transform и собственным вложенным SVG-viewport, чтобы сохранить ненулевое начало viewBox и системы координат ресурсов. Стили фиксируются inline, CSS-таблицы удаляются, ID и локальные ссылки изолируются. Угол нормализуется только для экспортного transform; параметры рабочего проекта не меняются. Фон не добавляется. SVG-файл не содержит служебного UI-состояния и не заменяет JSON-проект.
