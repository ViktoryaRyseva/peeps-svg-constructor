## Воспроизведённые технические дефекты

### D-01. Молчаливое повреждение при transform-origin

Минимальный вход: SVG с viewBox `0 0 200 200`, группа `transform="rotate(30)" transform-origin="50% 50%"`, внутри красный прямоугольник. Парсер принимает документ; выбор группы и извлечение завершаются без ошибки. После создания меньшего viewport процентный центр поворота начинает означать другую точку.

Точка прямоугольника после нормализации должна оказаться в `(10, 0)`, а оказывается примерно в `(-42,893; 29,764)`. Ошибка — **60,69 SVG-единицы**. Контрольный рендер полученного файла содержит **0 окрашенных пикселей**: прямоугольник полностью уходит за его границы.

Причина: [base.ts](../src/svg/base.ts#L44) принимает атрибут, а [клонирование оформления](../src/svg/base.ts#L125) сохраняет процентный transform-origin без фиксации его прежней системы координат. Новая геометрия viewBox меняет результат. Это не вопрос красоты выделения: файл уже неверен и пользователю не сообщается отказ.

**Могу сам:** сначала гарантировать безопасный отказ на неподдерживаемой конструкции вместо пустого результата; затем реализовать и проверить перенос центра/матрицы, если поддерживаем этот случай. Нового решения пользователя для предотвращения повреждения не нужно. Полноценный перенос надо проверять на группах, ненулевых viewBox и вложенных трансформациях, а не лечить только пример.

Артефакты: [оригинал](stages-11-12-audit-artifacts/transform-origin-original.svg), [неверный результат](stages-11-12-audit-artifacts/transform-origin-extracted.svg), `transformOriginExtraction` в [наблюдениях](stages-11-12-audit-artifacts/deep-observations.json).

### D-03. Числовая устойчивость

Поворот `1e308` считается конечным и допускается полем; последующее изменение ширины даёт NaN в координатах и scaleX. Экспорт теперь отказывается от неконечной геометрии, но сам рабочий экземпляр уже повреждён. Отдельно хранилище допускает конечный scaleX, произведение которого на ширину SVG равно Infinity.

См. [TransformFields.tsx](../src/components/TransformFields.tsx#L13), [transforms.ts](../src/services/transforms.ts), [storage.ts](../src/services/storage.ts). **Могу сам:** проверять результат вычислений до изменения состояния/записи, стабилизировать тригонометрию и вычисления масштаба, определить технические пределы для холста 1200 × 800. Это не требует расширять функциональность.

### D-04. Кириллические ID ресурсов

Документ с `<linearGradient id="градиент">` и `fill="url(#градиент)"` корректно отображается. Извлечение завершается ошибкой: «Зависимость `%D0%B3%D1%80...` отсутствует или имеет повторяющийся ID».

[resources.ts:4](../src/svg/resources.ts#L4) берёт fragment из URL в кодированном виде и сравнивает с исходным DOM id без согласованной нормализации. **Могу сам:** привести разрешение локальных URI-ссылок и DOM ID к единой форме, проверить Unicode и буквальные проценты, не подменяя неоднозначные ссылки догадкой. Выбор нового набора исходников для исправления не нужен.

### D-05. Анимация в библиотеке статических SVG

Через обычный диалог загружен SVG с `@keyframes`, меняющим цвет прямоугольника. Он сохраняется в библиотеку; две последовательные миниатюры реально красная и синяя. При открытии для выделения общий обработчик уже отклоняет CSS at-rules.

Причина: [svgUpload.ts](../src/services/svgUpload.ts) запрещает часть SMIL и некоторые CSS-конструкции, но не CSS-анимации. Скриптового исполнения этим не доказано: воспроизведена именно анимация SVG-изображения. Помимо несоответствия статичности это создаёт риск фоновой нагрузки при нескольких превью.

**Могу сам:** согласовать проверку статического содержимого до сохранения/создания превью с текущими правилами MVP. Предупреждения только при открытии недостаточно, потому что превью уже анимируется. Доказательства: [кадр A](stages-11-12-audit-artifacts/animated-preview-a.png), [кадр B](stages-11-12-audit-artifacts/animated-preview-b.png).

### D-06. Повреждённый path и утечка

`<path d="M 0 0 L"/>` проходит XML/загрузку. Ошибка парсера геометрии возникает после создания скрытого probeHost, до получения SelectionModel вызывающим кодом. Десять попыток оставляют десять контейнеров. Пользователь видит техническое английское сообщение.

См. [topology.ts](../src/svg/topology.ts#L26), [model.ts](../src/svg/model.ts#L30). **Могу сам:** гарантировать очистку при неуспешном конструировании и понятный отказ на повреждённом контуре. Продолжать работу с неповреждённой частью файла необязательно: безопасный отказ в рамках MVP достаточен.

### D-07. Доступ к объектам вне холста

При добавлении 36 экземпляров последние три получают Y=810 при высоте холста 800. К этому же приводит обычный ввод координат или движение. Элементы остаются в проекте, но холст обрезает содержимое, списка экземпляров и команды возврата нет. После снятия выделения/открытия проекта выбрать их мышью нельзя; клавиатурная кнопка существует, но её трудно обнаружить.

См. [views.ts](../src/services/views.ts#L15), [CompositionCanvas.tsx](../src/components/CompositionCanvas.tsx). **Могу сам:** удерживать стандартное размещение внутри видимой области и добавить доступный возврат. Согласованное право размещать графику за границами не следует молча отменять жёстким запретом движения.

### D-08 и D-09. Несовпадающие границы загрузки и работы

SVG с числовыми width/height без viewBox, text, локальным use сохраняются, но выделение не открывается. Это ранее задокументированный разрыв между хранением и обработкой, а не новое доказательство небезопасности этих файлов.

Дополнительно проверен **собственный файл экспорта**: загрузчик принимает его, однако открытие для выделения выдаёт «Вложенные SVG-области пока не поддерживаются». Экспорт содержит вложенные viewport намеренно: они сохраняют системы координат и обрезание компонентов. Удалить их без пересчёта — значит получить новый риск геометрии.

**Самостоятельно могу** показать совместимость до сохранения, пометить недоступное выделение и сделать ошибку понятнее. **Ваше решение нужно**, если хотим либо ужесточить библиотеку до редактируемого подмножества, либо поддержать повторное выделение из собственного экспорта. Последний вариант требует отдельного переноса вложенных viewport, обрезания и ресурсов. Исходное PDF не обязывает поддерживать любой SVG или такой цикл повторной загрузки, поэтому D-09 не следует выдавать за безусловное нарушение PDF.

### D-11. Рамка мелкой детали

У детали размером 3 × 8 рамка рисуется не меньше 32 × 32 экранных базовых пикселей. Resize рассчитывает якорь по настоящим размерам. При движении нижнего правого маркера видимый противоположный маркер смещается примерно на **7,73 px**, хотя противоположный геометрический якорь остаётся фиксированным.

См. `.transformFrame` в [App.module.css](../src/App.module.css), [transforms.ts](../src/services/transforms.ts#L29). **Это не подтверждение порчи сохраняемых координат.** Это несоответствие между видимой рамкой и геометрией, особенно заметное на глазах/рте. Могу реализовать исправление; нужно выбрать удобное поведение минимальной рамки/маркеров. Числовые поля остаются рабочим обходным способом.

### D-12. Неподтверждённый числовой ввод

В сохранённом проекте ввести X=321, не нажимая Enter и не выходя из поля, затем перезагрузить страницу. В модели ещё X=160, dirty=false, нативного предупреждения нет, введённый текст теряется.

В README подтверждение числа через Enter/выход из поля описано, поэтому это **не потеря уже подтверждённой трансформации** и не нарушение обещанного автосохранения: его нет. Но визуально пользователь уже редактирует значение и может ожидать защиты.

Нужно решить, учитывать ли незавершённый ввод в черновике. После этого могу самостоятельно отделить текстовый черновик поля от применённой геометрии и учесть его в защите. Предположение о необходимости двух кликов «Сохранить» **не подтвердилось**: обычный клик корректно фиксирует blur и открывает сохранение.

## Риски, требующие инженерной проработки

### D-02. Бюджет обработки и отзывчивость

Нет ограничения размера файла, суммарного объёма пачки, количества узлов, команд всех путей и общей длительности подготовки. Файлы читаются одновременно; XML, часть анализа и измерений выполняются в основном потоке. Лимиты 128 подконтуров/5000 сегментов применяются к отдельному пути, причём после части дорогой работы.

В ограниченной диагностике SVG на 20 000 прямоугольников, 560 067 байт, принят. Это подтверждает отсутствие лимита узлов, **не предельное зависание**. Преднамеренно исчерпывать память или подвешивать браузер не пытался.

Нужна моя отдельная проработка: ранние бюджеты, ограниченный параллелизм, граница между Worker-геометрией и обязательным SVG DOM, отмена/тайм-аут, сохранность черновика при отказе. Одно число «максимальный размер файла» не закрывает глубину дерева и сложность геометрии. Ваше участие — предоставить остальные исходники и тяжёлые примеры, если такие нужны продукту. Полную поддержку спецификации SVG для этого добавлять не требуется.

### D-10. Стоимость dirty-check

На каждом рендере App для изменяемой композиции вызывается snapshot, сериализующий полные SVG. При pointermove это повторяется. В отдельном измерении на текущем компьютере:

| Экземпляров | Символов в снимке | Медиана одной сериализации | Максимум из 5 |
| --- | --- | --- | --- |
| 10 | 424 241 | около 0,5 ms | около 1,6 ms |

## Решения и материалы, для которых нужны вы

### D-13. Переносимость и резервирование

IndexedDB привязана к адресу сайта, порту, профилю браузера. Публикация на другом origin не переносит существующую библиотеку; очистка данных сайта удаляет её. Автоматического восстановления черновика и файлового резервного JSON нет. SVG-экспорт сохраняет картинку, но не является импортируемым внутренним проектом редактора.

Это согласованное ограничение MVP, а не невыполненный файловый JSON-экспорт этапа 10. Нужно ваше решение, остаёмся ли при локальном хранении с явным предупреждением или добавляем переносимый проект/резервную копию. Сервер, аккаунты и синхронизация для этого необязательны. После выбора файловый сценарий могу реализовать сам; до публикации нужно отдельно учесть существующие данные на текущем origin.

### D-14. Комплект 20 исходников

Исходное PDF требует библиотеку 20 SVG в едином стиле, при этом разрешает показать извлечение только на нескольких. Эти условия различны. Сейчас есть три предоставленных Peep, а остальные 17 ранее обещаны вами. Согласие временно работать с тремя не превращает итоговое требование в выполненное.

Нужны обещанные файлы. После их появления могу проверить стиль/формат, поддержку, подготовить копии, добавить библиотеку и выявить новые геометрические случаи. Заменять выбранную вами библиотеку чужими источниками без решения не следует. Автоматически извлекать все части всех двадцати PDF не требует.

### D-15 и D-16. Целевые редакторы и браузеры

Проверены Chrome и, на этапе 10, внешний системный просмотрщик Quick Look. **Редактирование объектов** после импорта в Illustrator/Inkscape/Figma не проверено. Наличие path/групп вместо растра — необходимая, но не полная проверка поведения конкретного редактора. Особенно надо проверить вложенные viewport, маски, clipPath, стили и повторное сохранение.

Нужно выбрать редактор для обязательной приёмки. Далее могу подготовить файлы и техническую проверку; если в этой среде нет способа выполнить нужный импорт/редактирование, потребуется ваша ручная проверка. Quick Look не следует выдавать за векторный редактор.

Safari на Mac и Firefox не прошли полный прогон, как и длительная сессия с большими библиотеками. Нужно определить обязательные браузеры. Могу расширить автоматизацию доступными движками; проверка WebKit сама по себе не равна полной проверке конкретного Safari. Исходное задание не требует поддерживать все браузеры и мобильные устройства без ограничений.

### D-17 и D-18. Передача проекта

`git ls-files` показывает только README.md; код, lock-файл, настройки и материалы остаются untracked. Remote origin настроен, но это не доказывает наличие кода в удалённом репозитории. Поэтому успешная сборка копии рабочего каталога не равна воспроизводимости из текущего коммита.

**Могу сам после разрешения на исправления:** подготовить корректный состав репозитория, необходимые тестовые эталоны и инструкцию. Ваше решение понадобится по публикации/доступу и финальной ссылке; в этом аудите коммиты и отправка не выполнялись.

В исходном PDF также требуются список AI-инструментов, 2–3 примера композиций и короткая демонстрация. Есть технические SVG/PNG и отчёты, но нет единого оформленного комплекта с выбранными примерами и явным перечнем AI-инструментов. Несколько тестовых файлов автоматически не становятся качественной демонстрацией. Подготовку могу выполнить сам; выбор итоговой подачи/публикации желательно согласовать с вами. Дополнительная серверная инфраструктура для сдачи запускаемого проекта не обязательна.

### D-19. Документация

[README:25](../README.md#L25) всё ещё говорит, что сборка содержит две экспериментальные страницы. Фактически в dist один index.html, старые URL удалены, и ниже тот же README это подтверждает. В истории decisions.md также сохраняются ранние правила начальных позиций/порядка добавления, уточнённые поздними решениями. Историю можно оставить, но актуальное поведение должно быть однозначно выделено.

Могу исправить документацию самостоятельно. Сейчас не исправлял, чтобы не смешивать аудит и устранение замечаний.

## Что подтвердилось как корректное

- Штатный сквозной сценарий этапа 10 заново прошёл: три реальных исходника → извлечённые детали → библиотека → композиция → сохранение/перезагрузка/изменение → настоящий SVG-download.
- Загрузка неверного расширения/XML, пустые обычные имена и конфликты имён имеют проверки. Отмена выбора/имени/удаления и ошибки записи не превращаются в фиктивное сохранение.
- Удаление используемого компонента не ломает сохранённую композицию. Дополнительный сценарий удалил **все исходники и все библиотечные компоненты**, перезагрузил страницу и скачал композицию из её трёх прежних SVG-снимков; снимки совпали побайтно.
- Контроль версии сохранения после этапа 10 работает: попытка устаревшей вкладки не затёрла X=111 первой вкладки. Прежний A-01 не числится действующим дефектом.
- Девять ограниченных негативных случаев — script, обработчик события, foreignObject, растр, внешняя ссылка градиента, CSS import, внешняя заливка, SMIL animate и закодированный javascript href — отклонены загрузчиком. Это не исчерпывающий security-аудит; D-05 показывает отдельный пропуск статичности.
- Вырожденная scale(0)-геометрия отказывает с понятной ошибкой; отдельные stroke-only детали в проверенном случае доступны глубоким выбором. Эти подозрения не стали дефектами отчёта.
- Сохранение через клик после незавершённого числового ввода срабатывает: blur фиксирует значение до открытия диалога. Дефект двух обязательных кликов не подтверждён.
- Не добавлены авторизация, серверная часть, рисование новой графики или генерация объектов, противоречащие рамкам PDF.
