# Этап 10. Сохранение, повторное открытие и SVG-экспорт

18 октября 2026 года. Основание: «материалы/Этапы 10-12.docx», раздел этапа 10, и REQ-35–39. Реализация встроена в основной редактор; экспериментальные страницы не возвращались.

## Результат

«Экспорт» → подтверждение теперь скачивает самостоятельный векторный SVG текущей композиции. Корень имеет `width="1200"`, `height="800"`, `viewBox="0 0 1200 800"`. Фон прозрачный, порядок наложения соответствует холсту. Перемещение, разные масштабы осей и поворот сохраняются. Рамки выделения, сетка и интерфейс не входят в файл.

Экспорт работает и для несохранённой непустой сцены. Отмена ничего не меняет; скачивание не закрывает документ, не сохраняет проект автоматически, не сбрасывает dirty/выделение/zoom и не изменяет библиотеки. При ошибке диалог остаётся с причиной, скачивание повреждённого/частичного файла не начинается.

Сохранение нового проекта запрашивает уникальное имя; существующий открывается со всеми параметрами, изменяется и перезаписывается после подтверждения. JSON-проект по-прежнему хранится в IndexedDB со встроенными SVG экземпляров. Файловый импорт/экспорт JSON не добавлялся: это не инструкция этапа 10.

## Защита сохранения

Устранён A-01 из аудита этапов 1–9: устаревшая вкладка больше не перезаписывает новую версию и не восстанавливает молча запись, удалённую другой вкладкой.

- Открытый документ запоминает `updatedAt` как ожидаемую ревизию.
- Чтение текущей версии, сравнение и запись выполняются в одной read/write-транзакции IndexedDB.
- Ревизия строго возрастает, в том числе при нескольких сохранениях за миллисекунду.
- При конфликте остаются рабочий черновик и диалог с причиной. «Сохранить копию» запрашивает новое уникальное имя и создаёт другой ID, сохраняя обе версии.
- Только успешная запись обновляет baseline и ревизию. Guard-переход продолжает действие после успешного сохранения; ошибка/отмена его не выполняют.

Схема базы version 1 не менялась; пользовательские записи не мигрируются и не очищаются. Автоматическое обновление библиотек другой вкладки не добавлялось — конфликт проверяется в момент записи.

## Как устроен SVG-файл

`src/services/compositionExport.ts` собирает отдельный SVG DOM из неизменяемых снимков экземпляров. Для каждого создаются группа с transform и вложенный SVG-viewport. Внутри остаются настоящие path, группы, градиенты, маски и clipPath. Вложенный viewport сохраняет собственный viewBox, его ненулевое начало, процентные координаты ресурсов и обрезание исходного изображения. Размер композиции не подгоняется под содержимое.

Полные деревья клонируются через `freezeCompleteSvg` общего SVG-модуля: вычисленное оформление фиксируется inline, таблицы CSS и классы удаляются. Благодаря этому одинаковые CSS-селекторы разных компонентов не переоформляют соседей. Координаты ресурсов не пересчитываются по новым границам.

Каждый экземпляр получает UUID-пространство ID; локальные `url(#id)`, обычные/xlink href и поддерживаемые ARIA-ссылки обновляются. Повторяющиеся служебные ID без ссылок, встречающиеся в исходных Peep, переименовываются поэлементно. Если ссылка действительно неоднозначна, зависимость отсутствует или наследование градиента циклическое, экспорт выдаёт ошибку.

Вывод не содержит растровых image, canvas, foreignObject, скриптов или внешних файлов. Временные DOM-копии удаляются в finally; Blob URL освобождается после запуска скачивания. Извлечение деталей и оригиналы SVG не изменялись.

Для экспортной тригонометрии/transform используется угол по модулю 360; полный угол проекта сохраняется. Проверяются конечность производных размеров/центров и положительные масштабы. Это защита экспорта: общий дефект A-03 числового ввода в редакторе целиком этим не устранён.

## Приёмка

| Пункт этапа 10 | Реализация и проверка |
| --- | --- |
| Новая композиция с уникальным именем | Диалог имени, проверка и уникальный индекс IndexedDB; отмена и конфликт имени покрыты существующими проверками |
| Открыть, изменить, перезаписать | E2E сохраняет детали трёх разных исходников, собирает сцену, задаёт координаты/размеры/поворот/слои, сохраняет и перезагружает страницу; параметры совпадают точно; повторное изменение перезаписывается |
| Защита несохранённой работы | Существующие guard-сценарии и новый тест сохранения перед переходом; экспорт не снимает dirty; конфликт двух вкладок сохраняет черновик и позволяет копию |
| Самостоятельный векторный SVG | Настоящий download, чтение скачанного файла, открытие через file:// в отдельной странице Chrome; проверка XML, размеров, слоёв и path; независимое сравнение изображения; дополнительный рендер macOS Quick Look |

Проверки: **сборка успешна; 110 Vitest и 140 Playwright проходят**. Включены 12 новых проверок SVG-экспорта, две проверки конфликтов хранения и шесть новых E2E этапа 10. Прежний тест демонстрационного экспорта заменён проверкой настоящего скачивания.

Независимая визуальная проверка рисует исходные автономные SVG как отдельные изображения на Canvas с самостоятельно рассчитанными трансформациями, затем сравнивает их с растеризованным итоговым файлом. Случай включает конфликтующие CSS/ID, цепочку градиента, маску, clipPath, разные масштабы, повороты и отрицательное начало viewBox. Допуск учитывает сглаживание при разных способах рендера: средняя ошибка менее 1/255 на канал среди окрашенных пикселей, доля существенно отличающихся пикселей менее 2%. PNG/Canvas используются только для проверки; экспортируемое содержимое остаётся векторным.

Повторная диагностика A-01: после сохранения X=111 в первой вкладке попытка второй записать свою устаревшую версию оставляет в базе X=111; `firstTabChangeLost=false`. Старые наблюдения аудита сохранены отдельно.

## Границы проверки

Файл открыт и проверен в Chrome и обработан внешним системным просмотрщиком Quick Look. Узлы, ресурсы и трансформации сохраняются как редактируемая SVG-разметка. Ручной импорт в Illustrator/Inkscape/Figma не выполнялся; особенности конкретного внешнего редактора не объявляются проверенными.

Поддержка компонентов соответствует статическому подмножеству общего SVG-модуля. Произвольные text/use/symbol, фильтры и другие неподдерживаемые конструкции не получают фиктивный растровый экспорт: пользователь видит причину отказа.

Из прежнего аудита остаются A-02 (общие бюджеты обработки), A-03 (экстремальный числовой ввод), A-04 (ошибка подготовки повреждённого пути), A-05 (совместимость при загрузке), A-06 (возврат объектов из-за холста) и A-07 (профилирование больших сцен). Экспорт не означает их исправления. Остальные 17 исходников всё ещё ожидаются. Этапы 11–12 не объявляются завершёнными этим отчётом.
