## Этап 6. Библиотеки и локальное хранение

### Интерфейс

- Три папки «Исходники», «Компоненты», «Композиции» сохранены в соответствии с ранее принятой структурой интерфейса. Каждая раскрывается, имеет счётчик, ограниченную высоту и прокрутку.
- Превью исходников/компонентов построены по сохранённому SVG. Превью композиции показывает её экземпляры, а не один произвольный компонент.
- Иконка удаления доступна при наведении/фокусе; на узком экране постоянно видна. Перед удалением есть подтверждение с именем.
- Открытие файла — двойной клик или Enter. Загрузка не закрывает текущий документ и не сбрасывает выделение.

### Загрузка

1. Пользователь выбирает один или несколько файлов.
2. Проверяется расширение `.svg` без учёта регистра, читается настоящий текст файла.
3. DOMParser проверяет XML и SVG namespace. Активное содержимое, внешние ресурсы и растровые вставки отклоняются. Эта проверка отделена от более узкого подмножества извлечения этапа 3.
4. Ошибки привязаны к файлам. Корректные SVG остаются в очереди, некорректные не сохраняются.
5. Для каждого файла предлагается уникальное имя с редактированием. Сохранение выполняется только после подтверждения.
6. «Отмена» имени пропускает текущий файл; закрытие окна завершает оставшуюся очередь. Уже сохранённые файлы не удаляются. Отмена чтения не позволяет позднему результату чтения попасть в новую очередь.

SVG хранится исходным текстом. Содержимое не подменяется образцом и не растеризуется.

### Уникальность и ошибки

Имя нормализуется: trim + NFC + регистронезависимое сравнение, отдельно в каждой библиотеке. Расширение фиксируется по типу и не удваивается при обычном вводе полного имени. Дополнительно `&nameKey` в IndexedDB защищает от конкурентных записей. Конфликт не перезаписывает другую запись.

UI обновляется только после успешного завершения операции IndexedDB. При ошибке имени, нехватке места или недоступности хранилища диалог остаётся открытым. Ввод и активный документ сохраняются. Во время записи закрытие/повторное подтверждение заблокированы. Если база недоступна при старте, приложение показывает ошибку и повторную загрузку, не создавая ложную временную библиотеку.

Первоначальные примеры добавляются через populate один раз при создании базы. Сетевое чтение образцов завершается до транзакции. Ошибка первого populate допускает повторное открытие без повторной регистрации обработчиков. Удалённые примеры не добавляются при следующем запуске.

### Автономность композиций

Проекты сохраняются со встроенными SVG и трансформациями экземпляров. Сервис не записывает URL превью, выделение, zoom и baseline. При удалении компонента уже сохранённые svgContent не меняются. При открытии проекта изображение берётся из экземпляра; библиотека компонента нужна только для отображаемого имени происхождения, если запись ещё существует.

Сохранение существующего проекта обновляет ту же запись после подтверждения. Некорректные размеры, пустая композиция, повторяющиеся ID экземпляров и нечисловые трансформации отклоняются. Слои нормализуются в последовательный zIndex.

**Итого: 45 Vitest + 29 Playwright = 74 проверки.**

В ходе работы исправлены конфликты временных артефактов при параллельном запуске отдельных Playwright-команд: итоговый прогон выполняется одним процессом. Старый тест загрузки заменил заглушку `<svg/>` на корректный SVG с namespace — реальная загрузка теперь справедливо отклоняет прежнюю заглушку. Это изменение проверки, а не ослабление валидации.
