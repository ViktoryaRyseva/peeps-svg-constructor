## 2. Лоадеры

Индикаторы добавлены при открытии файловой библиотеки, чтении/проверке загрузки, подготовке исходника к выделению, извлечении компонента, сохранении и экспорте. Перед синхронной обработкой пропускаются кадры, чтобы браузер успел показать индикатор. Для исходника подготовка отложена и отменяется при закрытии/переключении. Повторная операция блокируется сразу через ref, а не только после React-render. При ошибке индикатор снимается, диалог и данные сохраняются.

Это закрывает запрос на лоадер. Общие лимиты сложности SVG, анализ в Worker и полноценная отмена уже начавшегося синхронного расчёта не добавлены. Пункт D-02 исходного аудита шире одного индикатора; нельзя объявлять решённой всю задачу предельной нагрузки.

## 9. Собственный экспорт читается приложением

Экспорт и раньше был стандартным SVG. Проблема была в том, что экспортёр сохранял необходимые вложенные viewport, а обработчик исходника запрещал любую вложенность. Убирать viewport вслепую было бы неверно: они сохраняют координаты градиентов/масок, начало viewBox и обрезание.

Теперь поддержаны вложенные SVG с конечным viewBox и числовыми x/y/width/height, которые формирует экспортёр. Измерение использует полные getScreenCTM относительно корня. Временное дерево и выделение сохраняют вложенные области, а при выходе за корневой холст переносится явный clipPath. Все ID и локальные ссылки по-прежнему изолируются.

Рабочий сценарий: **экспорт композиции → «Загрузить SVG» → открыть исходник → выделить деталь → сохранить компонент → использовать и экспортировать снова**. Это проверено через настоящее браузерное скачивание. Также проверены независимые изображения с градиентом, маской, clipPath, поворотом и ненулевым началом viewBox. Допуск сравнения — максимум 2 единицы RGBA и менее 1000 изменённых каналов из 160 000; это не заявляется как нулевая разница. Частично обрезанный компонент повторно извлекается с правильными размерами видимой области.

SVG-импорт открывает рисунок для извлечения. Для восстановления всей сцены с отдельными экземплярами, ID и параметрами используется сохранённый JSON-проект. Это разные пользовательские сценарии; скрытая JSON-метаинформация в SVG не добавлялась. Процентные размеры вложенных viewport и другие прежние неподдерживаемые конструкции всё ещё имеют явные отказы.

## 13. Постоянные файлы в папках проекта

Про пользователей и авторизацию: в MVP их нет, библиотека одна для этого проекта. Отдельно про файловое хранение ранее не спрашивал; прежнее решение опиралось на IndexedDB из ТЗ. После уточнения рабочее хранение заменено локальным файловым API.

```text
peeps-svg-constructor/
  project-files/
    library.json
    sources/<UUID>.svg
    components/<UUID>.svg
    compositions/<UUID>.json
```

Пользовательские имена и ID находятся в library.json; UUID-пути не позволяют имени превратиться в путь к чужому файлу. SVG хранится исходной строкой. JSON содержит автономные SVG экземпляров: удаление компонента не повреждает композицию. При сохранении новой ревизии создаётся новый файл, затем атомарно переключается каталог. Неуспешная запись каталога оставляет прежнюю версию доступной. Файловая блокировка сериализует изменения; updatedAt защищает от перезаписи устаревшей вкладкой. Ошибки API не скрываются записью только в память/браузер.

Прежняя IndexedDB переносится автоматически без удаления. Повторный перенос одного набора не создаёт дубликатов. Конфликтующие записи сохраняются отдельными копиями с корректировкой ссылок. Удалённые образцы не восстанавливаются при следующем запуске. Старые версии и файлы удалённых записей физически остаются на диске, но не входят в видимую библиотеку; автоматическая очистка версий пока не добавлена.

Перезагрузка, очистка данных сайта и другой браузер не удаляют библиотеку, если приложение обращается к тому же серверу и каталогу. Для резервной копии/переноса нужно копировать всю папку project-files при остановленном сервере; она исключена из Git. Папку можно явно сменить через PEEPS_DATA_DIR. Несохранённый черновик автоматически не восстанавливается.

Запуск остаётся `npm run dev`; после сборки доступен `npm run preview`. Обе команды включают Node API. Одна статическая раздача dist через MAMP/иной веб-сервер API не создаёт. Авторизации, удалённой публикации и серверной синхронизации между компьютерами не добавлено.

## 12. Числовые поля

В текущем интерфейсе поля X/Y, ширины, высоты и поворота присутствуют в правой панели при выделении экземпляра композиции. При работе с исходником этих полей нет. Пункт 12 не исправлялся и не закрывался молча; текущая защита чисел из D-03 сохранена. Ввод числа до подтверждения и ухода из поля не превращён в автоматически сохраняемый черновик.

## Проверки

Полный набор запускается `npm test`: серверные файловые проверки, Vitest, регрессии Playwright и отдельные UI-сценарии файлового API. Тесты используют временные каталоги и новые браузерные контексты; папка пользовательского проекта не сбрасывается.

- Сервер: сохранность после создания нового сервиса, настоящие SVG/JSON, автономность, конкуренция имён и ревизий, отказ записи каталога, повторный перенос/конфликты, восстановление блокировки после сбоя.
- Браузер: загрузка и физические байты файла, чтение в новом контексте, настоящий download/import/extract/re-export, видимый лоадер и отмена подготовки, ошибка API с повтором, перенос прежней IndexedDB, конфликт вкладок и сохранение копии.
- SVG: независимые сравнения изображений, вложенные преобразования/ресурсы, корневое обрезание, повторное извлечение и прежние приёмочные сценарии.
