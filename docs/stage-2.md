# Этап 2. Прототип интерфейса и пользовательских сценариев

Дата: 18 октября 2026 года.

## Результат

Создан локально запускаемый интерактивный прототип на React + TypeScript + Vite с CSS Modules. Начальное состояние — пустой холст. Демобиблиотеки позволяют проверить сценарии без реализации извлечения SVG и постоянного хранения.

## Принятые интерфейсные детали

- Применён спокойный светлый интерфейс с оливковым акцентом. Для проверки состояний сразу доступны три исходника, три демокомпонента-персонажа и одна демокомпозиция.
- Имена файлов открываются двойным кликом или Enter. Отдельное удаление доступно также по клавиатурному фокусу; на узком экране его иконка видна постоянно.
- Клик по исходнику выбирает одну из условных областей «Голова»/«Поза». Эти области нужны только для проверки выбора и доступности сохранения. Они не являются результатом определения геометрии SVG.
- Клик/Shift-клик применяются также к экземплярам. Enter/Shift+Enter позволяют выбирать их с клавиатуры, включая перекрытые экземпляры.
- До подтверждения перехода текущий документ не заменяется. Отмена попапа выбора, защитного диалога или имени сохраняет текущую работу.
- Загрузка и экспорт не переключают режим и не снимают признак изменений. Отмена очередного файла при вводе имени позволяет продолжить очередь; закрытие окна завершает оставшуюся очередь. Уже сохранённые демозаписи остаются.
- Сохранение и перезапись выполняются только в памяти. Удаление библиотечного компонента не убирает его экземпляры с открытой сцены.
- На узком экране панели остаются доступны, действия переносятся по строкам, рабочая область имеет внутреннюю прокрутку. Основной сценарий редактора рассчитан на компьютер с мышью и клавиатурой.

## Проверка

`npm run build` — успешная проверка TypeScript и production-сборка.

`npm run test:prototype` — девять браузерных сценариев на установленном Google Chrome:

1. Пустой холст, папки, неактивные действия, отмена/Escape.
2. Исходник, Shift-выбор, конфликт имени, сохранение и завершение выделения.
3. Мультивыбор при создании композиции, выбор экземпляров, дублирование/удаление, границы слоёв, имя, отказ/подтверждение перезаписи и zoom без изменения данных.
4. Защита перехода: отмена, отмена имени, успешное сохранение с переходом и «Не сохранять».
5. Пофайловая очередь загрузки, отказ неподходящему расширению, отмены и экспорт без закрытия документа/скачивания.
6. Отмена/подтверждение удаления компонента, сохранность сцены, удаление открытой композиции.
7. Повторное открытие не сбрасывает черновик; после удаления всех экземпляров сохранение/экспорт недоступны, изменения остаются несохранёнными.
8. Подтверждение открытия компонента, доступность основных действий и отсутствие горизонтального переполнения страницы на экране 390 × 844.
9. Отсутствие ошибок приложения в консоли и отсутствующих ресурсов в проверенном сценарии.

Во время первой проверки тест пытался нажать в центр оригинала, перекрытого его дубликатом. Тест исправлен на клавиатурный выбор; приложение сохраняет обычное поведение слоёв. Снимки основных состояний просмотрены визуально. Проверки не доказывают корректность будущего извлечения SVG.

## Граница выполненного

Не реализованы DOMParser/XMLSerializer, извлечение и изоляция SVG-зависимостей, реальные границы объектов, постоянное хранение, настоящий импорт содержимого SVG, перетаскивание/поворот/масштабирование экземпляров и скачивание результата. Превью демокомпонентов используют исходных персонажей целиком. Эти ограничения обозначены в интерфейсе и README; этап 3 не начат.

Прототип запускается по [README](../README.md). Файлы исходных материалов не изменены. SVG в `public/demo/` — копии трёх предоставленных оригиналов, без добавления меток или изменения изображения.
