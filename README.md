# Peeps — конструктор векторных композиций

Реализованы основные сценарии этапов 1–10: документация, извлечение SVG, постоянные библиотеки, сборка композиции и интерактивные трансформации. Текущее состояние выбранных исправлений — в [отчёте стабилизации](docs/stabilization.md). Остальные замечания — в [аудите этапов 11–12](docs/audit-stages-11-12.md). React + TypeScript + Vite + CSS Modules + Zustand; файлы хранятся на диске через локальный Node API. [Лоадеры, повторный импорт и хранение](docs/local-files.md).

Новый SVG-обработчик внедрён в основной редактор: откройте исходник, выделите группу или детали лица и сохраните самостоятельный SVG в библиотеку компонентов. [Отчёт этапа 7](docs/stage-7.md), [предварительная проверка алгоритма](docs/stage-3-v2.md).

## Запуск

Нужен Node.js 24.14.0+ и npm (нижняя граница задана зависимостью `svg-pathdata@9`). Проверено на Node.js 25.6.1 / npm 11.9.0.

Из каталога `peeps-svg-constructor`:

```sh
npm install
npm run dev
```

Для установки точно по lock-файлу используйте `npm ci` вместо `npm install`. Откройте адрес Vite из терминала, обычно `http://127.0.0.1:5173`. Команда запускает редактор и локальный файловый API. PHP/MAMP не требуется. Остановка — Ctrl+C. `npm run preview` также подключает API; статическая раздача dist без Node не поддерживает файловую библиотеку.

```sh
npm run build
npm run preview
```

Сборка содержит один основной редактор; отдельные страницы экспериментов удалены. Публикация не настроена.

## Что работает

- Три раскрываемые библиотеки с именами, превью, прокруткой и подтверждаемым удалением.
- Настоящий SVG на холсте исходника. Один клик — ближайшая группа, двойной — мелкая деталь, Shift + клик — добавить/исключить деталь, Esc — снять выделение. Масштаб просмотра 50–200%.
- Извлечение выделения с собственным viewBox, стилями, градиентами, масками и clipPath в рамках поддерживаемого подмножества. Перед сохранением — превью, размеры и редактируемое уникальное имя. В библиотеку записывается только извлечённый SVG; исходник не изменяется.
- Множественная загрузка настоящих SVG: проверка расширения без учёта регистра, чтение файла, проверка XML/namespace и статического векторного содержимого. Ошибки показываются пофайлово, корректные файлы остаются в очереди.
- Пофайловый ввод имени. Пустое/некорректное имя и Unicode/case-дубликат отклоняются. Проверка имени выполняется под файловой блокировкой и защищает от конкурентных записей.
- Сохранение исходников, компонентов и проектов композиций в папках `project-files/`. Перезагрузка восстанавливает сохранённые библиотеки. Превью строятся по сохранённому SVG, а не по временному адресу исходного файла.
- Композиции содержат собственные SVG-снимки экземпляров. Удаление исходного компонента не повреждает сохранённую сцену.
- Создание композиции из нескольких компонентов в порядке выбора, добавление в текущую сцену. Экземпляры имеют реальные размеры своего SVG.
- Перетаскивание одного или нескольких выбранных экземпляров, дублирование без новых файлов в библиотеке, удаление и соседние слои.
- Рамка трансформации: углы сохраняют текущие пропорции, боковые маркеры меняют одну ось, ручка вращает вокруг центра. Точные поля X/Y, ширины, высоты и угла. Escape отменяет активный жест.
- Масштаб просмотра 50–200%, точное сохранение/восстановление параметров и порядка слоёв, защита текущих изменений.
- Ошибки записи/удаления не скрываются: диалог остаётся открытым, данные не заменяются временной записью в памяти, действие можно повторить. При недоступном файловом API показывается ошибка с повторной загрузкой.

При первом создании файловой библиотеки без прежних данных один раз добавляются три предоставленных исходника, три компонента-персонажа целиком и композиция «Три характера». Их можно удалить; после перезагрузки они не появятся заново. Образцы не засчитываются как извлечение мелких деталей.

## Где хранятся данные

Рабочее хранилище — папка `project-files/` рядом с package.json:

- `sources/` — оригинальные `.svg`;
- `components/` — автономные `.svg` компонентов;
- `compositions/` — `.json` проектов со встроенными SVG экземпляров;
- `library.json` — каталог имён, ID, ревизий и путей.

Имена файлов на диске — UUID; пользовательские имена доступны в каталоге и интерфейсе. При сохранении создаётся новый файл, затем атомарно переключается каталог. Прежние версии и файлы удалённых записей физически сохраняются, но не появляются в библиотеке. Автоматическая очистка версий пока не добавлена. Для резервной копии или переноса копируйте **всю папку project-files** при остановленном сервере. В Git она исключена.

Перезагрузка, очистка данных сайта и смена браузера не удаляют эту библиотеку. У всех вкладок и браузеров, обращающихся к этому проекту, одни файлы. Пользователей и авторизации нет. Изменения другой вкладки видны после перезагрузки, автоматическое обновление списков не реализовано.

Найденные данные прежней IndexedDB автоматически переносятся без её удаления. Повторный перенос того же набора не создаёт дубликатов; конфликты сохраняются отдельными копиями. Если API недоступен, приложение показывает ошибку и не делает вид, что запись сохранена в браузере. Другая папка проекта или другой `PEEPS_DATA_DIR` означает другую библиотеку.

## Границы текущей версии

- Рот, нос, глаза и брови доступны отдельно на трёх Peep. Полная причёска не выделяется автоматически, если слита с головой в один непрерывный контур. Поддерживаемое подмножество и понятные отказы описаны в [отчёте этапа 7](docs/stage-7.md).
- Экспорт скачивает самостоятельный векторный SVG 1200 × 800 с прозрачным фоном, текущими трансформациями и слоями. Работает и для несохранённой композиции; не заменяет сохранение JSON-проекта на диске. Экспорт можно загрузить обратно как исходник, выделить деталь и сохранить новый компонент.
- При конфликте версий из разных вкладок перезапись отклоняется, черновик остаётся на холсте; доступно сохранение отдельной копии. JSON проекта хранится в папке compositions; пользовательский импорт/скачивание JSON через интерфейс не добавлялись.
- Сохранённая композиция восстанавливается; несохранённый черновик после перезагрузки не восстанавливается. Автоматического сохранения нет.
- Скачивание/импорт JSON не заявлены. Формат проекта описан в data-model.md.
- Остальные 17 SVG для итоговой библиотеки ожидаются от пользователя. Этап 10 выполнен; аудит этапов 11–12 и выбранные исправления проведены, финальная приёмка остаётся незавершённой из-за остальных пунктов аудита.

## Структура

- `src/components/` — библиотеки, диалоги, иконки.
- `src/store/` — Zustand библиотек и редактора.
- `src/services/` — файловый клиент, перенос прежней Dexie-базы, проверка SVG/имён, представления.
- `server/projectStorage.ts` — файловый API и атомарный каталог.
- `src/types/` — персистентные типы и отдельные рабочие/UI-типы.
- `src/tests/` — Vitest (`*.test.ts`) и Playwright (`*.spec.ts`).
- `src/svg/` — общий production-обработчик: парсинг, топология, виртуальное выделение, координаты ресурсов и экспорт.
- `src/components/SourceCanvas.tsx` — SVG-холст, события мыши, общая рамка выделения и жизненный цикл. Загружается при открытии исходника.
- `src/components/CompositionCanvas.tsx` — экземпляры и верхний слой рамок, Pointer Events и захват указателя.
- `src/services/transforms.ts` — размеры SVG, поворот, привязка противоположного угла/края, SVG-transform.
- `experiments/svg/` и `experiments/svg-v2/` — прежние модульные тесты и совместимые экспорты общего `src/svg`; отдельных страниц нет.
- `src/tests/fixtures/` — DOM и драйверы только для браузерных тестов; в production-сборку не входят.

## Проверки

Для браузерных тестов нужен установленный Google Chrome (`channel: chrome`). Дополнительный Chromium не скачивается.

```sh
npm run build
npm test
```

`npm test` последовательно запускает серверные файловые проверки, Vitest, регрессии Playwright и сквозные проверки файлового API. Не запускайте несколько команд Playwright одновременно в одном checkout: они используют общий каталог временных результатов.

Отдельные наборы:

```sh
npm run test:files
npm run test:unit
npm run test:file-ui
npm run test:libraries
npm run test:prototype
npm run test:svg:acceptance
npm run test:svg:v2
npm run test:stage7
npm run test:stages89
npm run test:stage10
npm run test:stabilization
npx playwright test svg-selection.spec.ts
```

Актуальные результаты: сборка, 5 серверных + 128 модульных + 148 прежних браузерных + 7 файловых UI-проверок — в [отчёте файлового хранения](docs/local-files.md). Результаты предыдущего набора — в [отчёте стабилизации](docs/stabilization.md). На этапе 10 было 110 Vitest и 140 Playwright; исторические результаты не означают закрытия всех замечаний аудита. В 52 визуальных случаях нового SVG-алгоритма максимальная разница пикселей равна нулю в проверенном Chrome. `npm run test:svg` сохранена как совместимая команда общего Vitest-набора.

Проверки используют настоящие SVG DOM и файловый API; старый набор IndexedDB сохранён для регрессий и миграции, getBBox не подменяется. Файловые тесты используют отдельные временные каталоги и не трогают project-files. Регрессии работают на порту 5174 в режиме test-browser, файловые UI-проверки — на 5175. Тесты с отказами записи точечно имитируют ошибку браузера; заполнение диска не производится. Новые снимки, сохранённые SVG и результаты интеграции находятся в `docs/stage-7-artifacts/`; прежние библиотеки — в `docs/stage-6-artifacts/`.

## Работа с исходником

Откройте исходник двойным кликом в библиотеке или кнопкой «Создать компонент». Двойной клик по видимому рту/глазу выбирает деталь; Shift + клик добавляет другие. Нажмите «Сохранить» в правой панели, проверьте превью, введите имя и сохраните. Новая запись появится в библиотеке компонентов и сохранится после перезагрузки. Отмена или ошибка записи оставляют выделение для повтора.

## Работа с композицией

Нажмите «Создать композицию», отметьте несколько компонентов и подтвердите. Перетаскивайте экземпляры; Shift + клик добавляет/исключает их из выбора. У одного выбранного экземпляра доступны восемь маркеров размера и ручка поворота. Числа можно ввести в правой панели и подтвердить Enter или выходом из поля. «Вперёд»/«Назад» меняют соседние слои. «Сохранить» записывает все параметры сцены в локальную библиотеку.

## SVG-проверки без отдельных страниц

Тестовые страницы этапов 3 и 7 удалены. Адреса `/experiments/svg/index.html` и `/experiments/svg-v2/index.html` возвращают 404 при запуске через Vite. Основной редактор и общий SVG-обработчик сохранены. Визуальные и кликовые проверки запускаются через тестовые DOM-фикстуры, без дополнительных HTML-точек входа и без включения драйверов в production-сборку.

Исторические SVG, независимые эталоны и метрики остаются в `docs/stage-3-artifacts/` и `docs/stage-3-v2-artifacts/`. Ссылки на экспериментальные страницы в старых отчётах описывают состояние на момент тех этапов.

[Аудит этапов 1–9](docs/audit-stages-1-9.md) и [расширенный аудит](docs/audit-stages-11-12.md) сохраняют исторические наблюдения. Их диагностические скрипты предназначены для воспроизведения прежних ошибок и могут останавливаться на новых защитных проверках. Актуальную проверку исправлений запускает `npm run test:stabilization`; функциональные проверки SVG и хранения входят в `npm run test:unit`.

## Экспорт композиции

Откройте или создайте непустую композицию, нажмите «Экспорт» и подтвердите скачивание. Файл содержит текущие изменения, включая ещё не сохранённые. Сетка, фон редактора и рамки выделения не экспортируются. Изменения в библиотеку записывает отдельная кнопка «Сохранить». Если проект успела изменить другая вкладка, сохраните свой черновик копией под новым именем.

## Совместимость SVG и возврат объектов

Перед сохранением загружаемого SVG показывается результат структурной проверки. Статические файлы с неподдерживаемой структурой можно сохранить и просматривать; они помечены «Только просмотр» с причиной недоступности выделения. Геометрия отдельных контуров и эффекты дополнительно проверяются при открытии/извлечении. CSS-анимации, переходы и SMIL не допускаются; старые такие записи не удаляются, а их превью блокируется.

SVG с `transform-origin` пока доступны только для просмотра: вместо неверного извлечения редактор показывает понятное ограничение. Русские и кодированные ID ресурсов поддерживаются. Новый экземпляр размещается в видимой области без изменения масштаба. Для полностью вышедших за границы экземпляров в правой панели есть «Вернуть на холст»; масштаб, угол и слои сохраняются. Намеренное перемещение за границы остаётся разрешённым.

Координаты по модулю и размеры ограничены 1 000 000 SVG-единиц, угол по модулю — 1 000 000 000 градусов; проверяются также производные размеры и центры. Недопустимый ввод не меняет прежний экземпляр. База данных и SVG-снимки не мигрируются и не очищаются.
