# Peeps — конструктор SVG-композиций

Веб-редактор для извлечения деталей из SVG-иллюстраций, сохранения компонентов и сборки новых векторных композиций. React, TypeScript, Vite и Zustand; локальный Node.js API хранит SVG и JSON в папках проекта.

## Запуск

Нужны Node.js 24.14.0+ и npm. Из корня проекта:

```sh
npm ci
npm run dev
```

Откройте адрес из терминала, обычно `http://127.0.0.1:5173`. Остановка — Ctrl+C. PHP/MAMP не требуется: команда запускает редактор и файловый API.

Сборка и запуск собранной версии:

```sh
npm run build
npm run preview
```

`preview` также подключает файловый API. Простая статическая раздача `dist` без Node API не обеспечивает работу библиотеки.

## Использование

1. **Исходник.** Нажмите «Загрузить SVG», выберите файлы, затем подтвердите имя каждого. Файлы появятся в библиотеке исходников.
2. **Компонент.** Откройте исходник двойным кликом или через «Создать компонент». Клик выбирает ближайшую группу, двойной клик — мелкую доступную деталь, Shift + клик добавляет/исключает деталь, Esc снимает выбор. Нажмите «Сохранить», проверьте превью и задайте имя. Исходник не изменяется.
3. **Композиция.** Нажмите «Создать композицию», отметьте компоненты и подтвердите. Перемещайте объекты мышью, меняйте размеры маркерами и вращайте ручкой над рамкой. Shift + клик выбирает несколько экземпляров. Справа доступны добавление, дублирование, удаление, соседние слои и точные параметры. Enter или выход из числового поля подтверждает ввод; Esc отменяет активный жест.
4. **Сохранение.** «Сохранить» записывает JSON-композицию в библиотеку. Повторное открытие — двойным кликом. При конфликте изменений разных вкладок можно сохранить отдельную копию. Полностью ушедшие за холст объекты возвращаются кнопкой «Вернуть на холст».
5. **Экспорт.** «Экспорт» скачивает текущее состояние как SVG 1200 × 800 с прозрачным фоном. Экспорт не заменяет сохранение проекта. Файл можно загрузить обратно как исходник и извлечь из него детали.

## Хранение

```text
project-files/
  library.json
  sources/<UUID>.svg
  components/<UUID>.svg
  compositions/<UUID>.json
```

Пользовательские имена, ID и пути связывает `library.json`. SVG записываются полным текстом; JSON-композиции содержат собственные SVG-снимки экземпляров. Удаление библиотечного компонента не повреждает сохранённую композицию.

Файлы сохраняются после перезагрузки, очистки данных сайта и смены браузера при обращении к тому же серверу. В MVP одна библиотека проекта, без пользователей и авторизации. Для другой папки задайте `PEEPS_DATA_DIR` при запуске; без него используется `project-files` в текущем рабочем каталоге.

Для резервной копии или переноса остановите сервер и скопируйте **всю папку `project-files`**. Она исключена из Git. Предыдущие версии файлов и файлы удалённых записей физически сохраняются, но не отображаются в библиотеке; автоматической очистки и резервирования нет. Несохранённый черновик и неподтверждённый ввод автоматически не восстанавливаются.

При обнаружении прежней IndexedDB данные переносятся в файлы без удаления браузерной базы. Повторный перенос того же набора не создаёт дубликатов; конфликтующие записи сохраняются отдельными копиями. Ошибка записи не закрывает диалог и не заменяется сохранением только в память.

При создании пустой библиотеки без прежних данных добавляются три исходника Peep, три компонента-персонажа и композиция «Три характера». Удалённые образцы при перезапуске не восстанавливаются.

## Поддержка SVG

Обработчик работает со статическим автономным векторным подмножеством: группы, пути, основные геометрические фигуры, поддерживаемые стили, градиенты, маски и clipPath. Поддержаны вложенные SVG с конечным viewBox и числовыми размерами. Результат остаётся векторным; изображения не растрируются и не дорисовываются.

Совместимость проверяется до сохранения. Статический SVG с неподдерживаемой структурой можно сохранить с пометкой «Только просмотр»; геометрия и ресурсы дополнительно проверяются при подготовке/извлечении. Внешние ресурсы, растровые вставки и анимация не допускаются.

Непрерывный контур не разделяется произвольно: например, причёска, слитая с головой, может остаться одним объектом. Text/use/фильтры, transform-origin и относительные размеры вложенных viewport имеют ограничения. Анализ геометрии выполняется синхронно с индикатором подготовки; неограниченная сложность файлов не предполагается.

## Структура

- `src/components/` — интерфейс, исходник, композиция и рамки управления.
- `src/svg/` — общий SVG-обработчик и топологический анализ.
- `src/services/` — хранение, валидация, геометрия и экспорт.
- `src/store/`, `src/types/` — состояние редактора и контракты данных.
- `server/` — локальный файловый API и его тесты.
- `public/demo/` — стартовые SVG.
- `src/tests/` — модульные и браузерные проверки; `assets/` и `fixtures/` содержат только тестовые входы и стенды.
- `scripts/verify-build.mjs` — проверка собранного приложения и сохранности файлов после перезапуска сервера.

## Проверки

Для браузерных проверок нужен установленный Google Chrome (`channel: chrome`).

```sh
npm run build
npm test
npm run test:preview
```

`npm test` последовательно проверяет файловое хранилище, модули, пользовательские сценарии и файловый API. `test:preview` собирает приложение и проверяет его после перезапуска сервера с новым браузером. Пользовательская библиотека не сбрасывается: проверки используют изолированные контексты и временные каталоги.

Отдельные наборы: `test:files`, `test:unit`, `test:e2e`, `test:file-ui`, `test:svg`, `test:components`, `test:composition`, `test:libraries`.

Не запускайте несколько Playwright-команд одновременно: у них общие каталоги результатов. Логи, изображения и другие результаты проверок находятся в игнорируемых `test-artifacts/` и `test-results/`; они не включаются в Git и production-сборку.
