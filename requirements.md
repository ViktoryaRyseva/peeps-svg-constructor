# Требования к веб-конструктору векторных композиций

Создано 18 октября 2026 года на этапе 1; актуализировано 19 октября по прямым уточнениям пользователя о файловом хранении и повторном импорте SVG. Исторические решения этапа 1 уточняются последующей перепиской.

## 2. Назначение и границы MVP

**REQ-01.** Сервис извлекает существующие объекты из SVG, сохраняет их как компоненты и позволяет собирать новые векторные композиции. Генерация изображений, дорисовывание новых объектов и растеризация результата не допускаются. AI может применяться для разработки сервиса.

**REQ-02.** Для конечной сдачи нужна библиотека из 20 исходных SVG в едином стиле. Сейчас предоставлены три; пользователь предоставит остальные 17. Разработка и ранняя проверка выполняются на трёх имеющихся. Это временное состояние входных данных, а не сокращение требования до трёх файлов.

**REQ-03.** Не требуется автоматически разбирать все 20 иллюстраций на смысловые объекты. Допускается подготовка копий SVG с явными метками выбираемых групп без изменения рисунка. Рабочий подход должен быть продемонстрирован на нескольких исходниках; минимальная демонстрация использует элементы не менее трёх разных исходных иллюстраций.

**REQ-04.** MVP работает в браузере с локальным хранением. Авторизация, серверная синхронизация, совместная работа, production-инфраструктура, полноценный аналог Figma и поддержка всей спецификации SVG не входят в MVP. Undo/redo, свободное рисование, редактирование контуров, перекрашивание объектов, импорт JSON и отдельное скачивание проекта JSON не заявлены как обязательные функции. JSON обязателен как внутренний формат сохранённой композиции.

**REQ-05.** Этапы выполняются последовательно. После этапа предоставляется отчёт по его чек-листу; при невыполненном пункте это явно сообщается. Несколько этапов в одном поручении выполняются только по явному указанию пользователя: 18.10.2026 разрешены этапы 4–6 из нового соответствующего документа. Доработка детализации извлечения отложена; этапы 7–12 этим разрешением не охвачены.

## 3. Термины и сущности

| Сущность | Определение и инварианты |
| --- | --- |
| Исходник / Source | Полный SVG-документ, загруженный пользователем, с собственными ID и уникальным в библиотеке именем. Извлечение никогда не изменяет его содержимое. Подготовленная копия отделена от оригинального материала. |
| Компонент / Component | Самостоятельный SVG-документ из одного или нескольких выбранных объектов: геометрия, оформление и необходимые зависимости, включая `defs`. Хранится в библиотеке компонентов; работоспособен без исходника. «Элемент» в БЭ означает компонент. |
| Экземпляр / Instance | Размещение компонента в композиции: собственная идентичность, SVG-снимок, координаты, масштаб по X/Y, угол поворота, место в порядке слоёв. Дублирование создаёт новый экземпляр, а не новый библиотечный компонент. |
| Композиция / Composition | Один или несколько экземпляров на фиксированном холсте; редактируемое сохранение в JSON. Пустое рабочее состояние — черновик, а не сохраняемая композиция. |
| Холст / Canvas | Рабочая область одного активного документа: исходника (ХИ) либо композиции (ХК). Масштаб просмотра не является трансформацией объекта. |
| Черновик компонента | Текущее непустое выделение в исходнике, ещё не сохранённое как компонент. Сам исходник от этого не становится изменённым. |
| Черновик композиции | Текущее состояние редактирования до сохранения либо изменения относительно последнего сохранённого состояния. |

БИ — библиотека исходников; БЭ — библиотека компонентов; БК — библиотека композиций. ЛБП, ВП, ПБП и НП — левая, верхняя, правая и нижняя панели соответственно.

**REQ-06.** Экземпляры автономны: при добавлении получают копию SVG компонента. Удаление исходника или библиотечного компонента не повреждает уже созданные компоненты, открытые черновики и сохранённые композиции. Ссылка на библиотечный компонент допустима как метаданные происхождения, но не как единственный источник его изображения.

## 4. Библиотеки и загрузка

**REQ-07.** ЛБП доступна во всех режимах. Содержит три раскрываемые папки: «Исходники», «Компоненты», «Композиции». Списки показывают имя и иконку, превью при наведении, имеют ограничение высоты и прокрутку. Справа при наведении появляется удаление. Просмотр папок сам по себе не переключает рабочий документ.

**REQ-08.** «Загрузить SVG» доступна всегда и открывает модальное окно поверх текущего процесса. Поддерживаются один и несколько файлов. Проверяются расширение `.svg` без учёта регистра, корректный XML и корневой SVG-элемент; расширения недостаточно. Ошибки показываются пофайлово, без потери корректных выбранных файлов и текущей работы.

**REQ-09.** Перед сохранением каждого загружаемого файла предлагается редактируемое уникальное имя, построенное на ID. Пользователь подтверждает «Сохранить» или выбирает «Отмена». Для множественной загрузки результат каждого файла независим: отмена ещё не сохранённого файла не удаляет уже сохранённые. Пакетное изменение всех имён не требуется.

**REQ-10.** Сохранение загрузки добавляет исходник в БИ. И сохранение, и отмена загрузки возвращают к тому же документу, выделению и черновику, которые были до модального окна. При исходно пустом холсте он остаётся пустым. Загрузка не открывает исходник автоматически и не вызывает защиту переключения документа.

**REQ-11.** Уникальность имён проверяется отдельно в каждой библиотеке после обрезки крайних пробелов, Unicode-нормализации и сравнения без учёта регистра. Расширение закреплено за типом: `.svg` для исходников/компонентов, `.json` для композиции. Пустое имя и имя с путевыми разделителями не принимаются. Конфликт имени показывает ошибку и оставляет диалог открытым; не перезаписывает другую запись. ID не зависит от имени.

**REQ-12.** Удаление любой библиотечной записи требует подтверждения с её именем. Отмена ничего не меняет. Подтверждение удаляет только эту запись; восстановления/корзины в MVP нет. Правила удаления открытого документа и зависимых сущностей описаны в `decisions.md`, D-09.

**REQ-13.** После перезагрузки страницы сохранённые записи трёх библиотек остаются в папках проекта на диске. Очистка данных сайта не удаляет их; пользователи и авторизация не требуются. Ранее использовавшаяся IndexedDB переносится без удаления. Автовосстановление несохранённого черновика не обещается. Ошибка локального сохранения не закрывает документ и не сбрасывает признак несохранённых изменений.

## 5. Режимы, панели и переходы

| Состояние | Холст | ВП | ПБП | НП |
| --- | --- | --- | --- | --- |
| Пусто | Пустое состояние | Загрузка, создание компонента и создание композиции доступны; экспорт неактивен | Скрыта | Кнопки видны, неактивны |
| ХИ | Исходник и выделение | Те же три действия доступны; экспорт неактивен | Видна: выделение; сохранение при непустом выделении; операции экземпляров серые | Масштаб просмотра активен |
| ХК | Черновик или сохранённая композиция | Те же три действия доступны; экспорт активен для непустой композиции | Видна: инструменты композиции по доступности | Масштаб просмотра активен |

**REQ-14.** ВП постоянно содержит «Загрузить SVG», «Создать компонент», «Создать композицию», «Экспорт». Кнопки не исчезают при недоступности: отображаются серыми и не нажимаются. Исключение — сама ПБП скрыта при пустом холсте.

**REQ-15.** Двойной клик по исходнику открывает ХИ; по композиции — ХК с сохранёнными данными; по компоненту задаёт вопрос «Создать композицию с этим компонентом?». «Да» создаёт новую композицию с его экземпляром через обычную защиту переключения; «Нет» сохраняет текущее состояние. Компонент не открывается в отдельном режиме редактирования.

**REQ-16.** «Создать компонент» предлагает выбор одного исходника; «Создать композицию» — выбор одного или нескольких компонентов. Пустую библиотеку сопровождает понятное предложение загрузить исходник/создать компонент. Отмена выбора сохраняет прежний рабочий процесс. На исходно пустом холсте остаётся пусто.

**REQ-17.** Переключение на другой исходник, композицию или новый процесс проверяет несохранённую работу до фактической замены активного документа. Неизменённый документ закрывается без лишнего подтверждения. При наличии несохранённого показывается «Сохранить», «Не сохранять», «Отмена».

| Ответ защитного диалога | Результат |
| --- | --- |
| Сохранить | Сначала успешно сохранить компонент или композицию, затем выполнить переключение. Отмена имени/перезаписи или ошибка сохранения отменяет переключение и сохраняет черновик. |
| Не сохранять | Отбросить текущий черновик/изменения и выполнить выбранный переход. Библиотечные записи этим ответом не удаляются. |
| Отмена | Закрыть защитный диалог; документ, черновик и выделение остаются. |

**REQ-18.** В ХИ несохранённая работа — непустое выделение для нового компонента. В ХК — отличия содержимого от последнего сохранения либо новая непустая композиция. Выделение экземпляра, открытие библиотек и масштаб просмотра не делают композицию изменённой. Экспорт не сохраняет JSON и не снимает признак изменений.

**REQ-19.** Переключение на тот же открытый документ не перезагружает его и не размножает экземпляры. Повторное открытие сохранённого документа после закрытия восстанавливает его данные, не изменяя библиотечную запись. Это смысл идемпотентности открытия.

## 6. Работа с исходником и извлечение

**REQ-20.** Исходник отображается без искажения цветов, геометрии и пропорций. Кнопки `−`/`+` меняют только масштаб просмотра.

**REQ-21.** Обычный клик выбирает один логический объект, снимая предыдущее выделение. `Shift + клик` добавляет/исключает объект. Выбирается ближайший явно помеченный логический предок либо помеченный поддерживаемый графический элемент. Клик по фону снимает выделение. Нельзя автоматически трактовать любой технический `g` или случайный `path` как смысловой объект. Если объект не подготовлен для выделения, интерфейс объясняет ограничение.

**REQ-22.** Один или несколько выбранных объектов сохраняются как один компонент с прежним взаимным расположением и порядком наложения. Одновременное извлечение предка и его потомка не дублирует графику. «Вырезание» означает копирование выбранной структуры, а не удаление из исходника, свободное лассо, разрезание контура или вычитание геометрии.

**REQ-23.** Перед сохранением компонента открывается диалог с редактируемым уникальным именем и кнопками «Сохранить»/«Отмена». Успех добавляет самостоятельный `.svg` в БЭ, оставляет исходник открытым и завершает текущий черновик выделения. Отмена оставляет выделение. Из одного исходника можно последовательно сохранять сколько угодно компонентов.

**REQ-24.** Парсинг — нативный `DOMParser`, сериализация — `XMLSerializer`. Компонент сохраняет геометрию, пропорции, цвета, эффективные стили, поддерживаемые градиенты, маски, клиппинг и контекст родительских трансформаций. Он должен корректно отображаться независимо от оригинала.

**REQ-25.** Переносятся все необходимые транзитивные локальные SVG-зависимости, а не только первый найденный `fill`. Проверяются ссылки в атрибутах и поддерживаемых стилях: в том числе `fill`, `stroke`, `clip-path`, `mask`, `filter`, `href`, `xlink:href` и `url(#id)`. Отсутствующая или неподдерживаемая зависимость приводит к понятной ошибке, а не к частичному сохранению испорченного компонента.

**REQ-26.** При извлечении, вставке/дублировании экземпляров и экспорте идентификаторы изолируются UUID-префиксом; одновременно обновляются все соответствующие локальные ссылки и поддерживаемые CSS-селекторы. Два одинаковых компонента на одном холсте не могут ссылаться на чужие определения. Точный UUID не является частью визуальной идемпотентности.

**REQ-27.** Компонент получает размеры по границам выбранной графики, а не по размеру исходника. Геометрия приводится к локальному началу координат с `viewBox="0 0 width height"`, сохраняя видимое изображение и взаимные положения. Нельзя просто удалять родительские `transform`. Нельзя считать необработанный `getBBox()` гарантированными визуальными границами при stroke, клиппинге и эффектах; случаи проверяются на этапе 3.

**REQ-28.** Границы SVG ограничены проверенным подмножеством. Базовая цель: статические векторные фигуры и группы, вложенные трансформации, атрибуты оформления и переносимые локальные стили, локальные градиенты, `clipPath`, маски. Локальный `use` и фильтры допускаются только после доказанного корректного переноса; не гарантируются заранее. Внешние ресурсы, скрипты, обработчики событий, `foreignObject`, растровые вставки и анимации в MVP не исполняются и не считаются поддерживаемым содержимым. Неподдерживаемое содержимое отклоняется с причиной, без молчаливого изменения изображения.

## 7. Сборка и трансформации композиции

**REQ-29.** Размер рабочей области композиции — 1200 × 800 SVG-единиц. При экспорте фон прозрачный. Сетка, фон интерфейса, рамки выбора и маркеры не являются содержимым композиции. Размер исходников и границы отдельных компонентов определяются их собственным SVG.

**REQ-30.** В ХК есть «Добавить элемент» с попапом БЭ и мультивыбором. Подтверждение добавляет независимые экземпляры; отмена ничего не меняет. Новый экземпляр располагается поверх предыдущих; порядок добавления определяет исходный порядок слоёв.

**REQ-31.** Выделенный экземпляр перемещается мышью. Поддерживается выбор нескольких экземпляров, дублирование и удаление выбранного набора. Дублирование не создаёт записей в БЭ и не связывает трансформации копии с оригиналом.

**REQ-32.** Рамка трансформации одного выбранного экземпляра имеет угловые маркеры пропорционального масштаба, боковые — независимого масштаба по X/Y, круглую ручку вращения относительно центра. Поворот и перенос работают независимо от масштаба просмотра. Масштабирование не превращает контуры в растровое изображение. Трансформации группы как единого объекта не обязательны; в MVP рамка изменения размера/поворота доступна при одиночном выборе.

**REQ-33.** «Вперёд» и «Назад» меняют один выбранный экземпляр местами с соседним слоем. При множественном выборе и на соответствующей границе действие неактивно. Дублировать/удалить можно несколько выбранных экземпляров; при пустом выделении эти действия неактивны.

**REQ-34.** Масштаб холста `−`/`+` меняет только отображение; координаты, масштабы экземпляров, размеры экспорта и сохранённые данные остаются прежними.

## 8. Сохранение, перезапись и экспорт

**REQ-35.** Новая непустая композиция сохраняется с предложением уникального редактируемого имени в БК. Внутренний JSON сохраняет размеры холста, автономные SVG экземпляров и все их трансформации/слои. Формальная схема будет описана на этапе 4.

**REQ-36.** Существующая изменённая композиция сохраняется после подтверждения перезаписи: «Да» обновляет ту же запись, старая версия теряется; «Нет» оставляет черновик и сохранённую версию без изменений. Успешное сохранение оставляет ХК открытым. Неизменённое состояние не требует повторного сохранения. История версий и «Сохранить как» не обязательны.

**REQ-37.** Пустой черновик нельзя сохранить как композицию или экспортировать. Если в ранее сохранённой композиции удалены все экземпляры, это несохранённое изменение: «Не сохранять» позволяет уйти без перезаписи старой версии; попытка «Сохранить» объясняет необходимость хотя бы одного экземпляра и оставляет текущий документ.

**REQ-38.** Экспорт доступен для текущей непустой композиции, включая ещё не сохранённую. Перед скачиванием требуется подтверждение (БК-08). Экспорт не закрывает документ, не меняет библиотеку и не заменяет сохранение JSON.

**REQ-39.** Экспортируемый SVG должен повторно загружаться как исходник приложения, допускать выделение детали и её сохранение компонентом. Восстановление отдельных экземпляров сцены относится к JSON-проекту. Экспортируемый самостоятельный SVG содержит `width="1200"`, `height="800"`, `viewBox="0 0 1200 800"`, корректный порядок слоёв, трансформации, стили и изолированные зависимости всех экземпляров. Графика остаётся векторной и пригодной для редактирования в стороннем редакторе. Превышение границ рабочей области не расширяет экспорт автоматически: область вывода фиксирована.

## 10. Проверка последующих этапов

На этапе 2 нужен только интерактивный каркас панелей, состояний, попапов и переходов. Полноценное извлечение и хранение не относятся к нему. Стек и инфраструктура вводятся в объёме, необходимом для прототипа; их окончательная организация — этапы 4–5.

На этапе 3 проверяются три реальных SVG и отдельные тестовые SVG с локальными стилями, градиентами, масками, клиппингом и вложенными трансформациями. Требуются DOMParser/XMLSerializer, программный выбор, клик/Shift-клик, корректные границы, перенос зависимостей, повторное изолированное отображение и понятный отказ неподдерживаемому случаю. Vitest проверяет логику; достоверность геометрии и отображения проверяется в реальном браузере, не подменяется фиктивным `getBBox()`.

На функциональных этапах используются Vitest для SVG-логики и Playwright для предусмотренных сквозных сценариев. Обязательны проверки отмены, конфликта имён, ошибок SVG/хранения, удаления используемого компонента, защиты изменений и повторного добавления одинаковых SVG без коллизий ID.

Финальный сквозной сценарий: открыть исходник → выделить объект → сохранить компонент → повторить для минимум трёх разных исходников → собрать сцену → сохранить и открыть её без потери параметров → экспортировать самостоятельный SVG.
